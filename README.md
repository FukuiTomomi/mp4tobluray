# mp4tobluray

mp4をBlu-ray(BDMV形式)のISOに変換し、BD-Rに書き込むスクリプト。
元動画の解像度・フレームレートを、Blu-ray規格内の形式に自動で変換する。

## 依存ソフトウェア

以下のコマンドがPATHに通っていること(通っていなければ `mp4tobluray.py` 冒頭の `FFMPEG` などにフルパスを書く)。

| ソフト | 用途 | スクリプト内の名前 |
|---|---|---|
| ffmpeg(libx264入り) | 映像・音声のエンコード | `ffmpeg` |
| ffprobe | 元動画の解析、出力の検査 | `ffprobe` |
| tsMuxer | BDMV構造への多重化 | `tsMuxeR` |
| ImgBurn | UDF 2.50のISO作成、BD-Rへの書き込み | `ImgBurn.exe` |

## Python

- Python 3.8以上
- 外部ライブラリは不要


## 使い方

### 実行時のコマンド

```
python mp4tobluray.py <入力mp4> <出力フォルダ> <BDドライブ> <mode>
```

例:

```
python mp4tobluray.py "D:\movie\input.mp4" D:\output E: 0
```

### おすすめの手順

1. modeを`0`にして実行 (5分間テスト)
2. 出力されたISOを確認:[出力ISOファイルの確認](#出力isoファイルの確認)を参照
3. modeを`1`にして実行 (ISOを作成)
4. 出力されたISOを確認:[出力ISOファイルの確認](#出力isoファイルの確認)を参照
確認か終わったらISOのマウントを解除してから手順6の書き込みを行う。
6. modeを`2`にて実行(BD-Rへの書き込み)
</br>※Blurayドライバーの扉を途中で閉める作業が必要な場合あり</br>
ImgBurnの仕様上Verifying Sessionの前にドライブの扉が開く
自動で閉められないドライブの場合は、手動で扉を閉めなおしてからImgBurnのタブをOKするとプロセスが再開する


| mode | 動作 |
|---|---|
| 0 | 先頭5分だけで、ISO作成まで一通り実行する(PC上の検査用) |
| 1 | 全編でISOを作成する |
| 2 | mode 1 で作ったISOをBD-Rに書き込む |


## 出力ファイル(出力フォルダ内)

中間ファイル名は、元のファイル名から日本語や空白を除いた名前になる。

| ファイル | 内容 |
|---|---|
| `<名前>.264` | 映像のみ(再エンコード済み) |
| `<名前>.ac3` | 音声のみ(AC3 48kHz) |
| `<名前>_BDMV/` | tsMuxerが作ったBDMV(`BDMV` と `CERTIFICATE`) |
| `<名前>.iso` | UDF 2.50のISO |
| `<名前>_2pass-0.log` ほか | 2パスエンコードの解析ファイル |

mode 0 の場合は、出力フォルダ内の `test` フォルダに、名前の末尾に `_test` を付けて出力される。
テストをやり直すときや不要になったときは、`test` フォルダを削除すればよい。

## 出力形式の自動選択
以下の条件で出力形式は自動選択されている。

| 元のfps | 元の高さ | 出力 |
|---|---|---|
| 24.5未満 | 720以下 | 720p23.976 |
| 24.5未満 | 721以上 | 1080p23.976 |
| 24.5〜45未満 | 問わず | 1080i29.97 |
| 45以上 | 1000以下 | 720p59.94 |
| 45以上 | 1001以上 | 1080i29.97 |

映像ビットレートは、尺からBD-R 25GBに収まるよう自動計算する(上限は `MAX_VIDEO_KBPS`)。

## 途中からの再開

- 出来上がっている `.264` と `.ac3` は再利用され、エンコードはスキップされる。
- 2パスのパス1が完了していれば、パス2から再開できる。
- BDMVとISOは、毎回作り直す。
- **エンコード設定を変えたときは**、出力フォルダの `.264`、`_2pass-0.log`、`_2pass-0.log.mbtree` を手で削除してから実行する。

## 実行時の注意

- 空き容量: 中間ファイルとISOで、合計60GB以上(出力上限DISC_BYTES×2倍＋α)確保
- スリープを切る: 動画によっては数時間かかるが、スリープ状態になるとやり直しになる。電源設定は「高パフォーマンス」推奨。


## 所要時間

ffmpegで映像を再エンコードする際のpresetオプション(mp4tobluray.pyの冒頭で定義されていPRESETという変数）でエンコード時間を調整することが可能。
このスクリプトでは2パスは固定。

#### 例：i7-12700F(Pコア8+Eコア4、20スレッド)構成での動画(2時間39分)の見積もり

| 出力形式 | preset | 2パス合計の目安 |
| --- | --- | --- |
| 720p59.94 | medium | 約1.5〜2時間 |
| 720p59.94 | slow | 約2.5〜3時間 |
| 1080i29.97 | medium | 約1.5〜2時間 |
| 1080i29.97 | slow | 約3時間前後 |

実際にはmode 0の5分版の所要時間を(動画時間/5)倍すれば、より正確な所要時間見積が可能。
**medium** でもslowとの画質差は小さく、時間は2〜3割短くなるので時間優先なら `PRESET = "medium"`に変更してよい。

## 出力ISOファイルの確認

1. 実行時の出力結果を確認し、検査結果OKと表示されているか(validateの出力)
    
    ```bash
    [検査] 合計サイズ 0.67 GiB / 上限 22.61 GiB
       {'codec_name': 'h264', 'codec_type': 'video', 'width': 1280, 'height': 720, 'r_frame_rate': '60000/1001'}
       {'codec_name': 'ac3', 'codec_type': 'audio', 'sample_rate': '48000', 'r_frame_rate': '0/0'}
      キーフレーム間隔 最大 1.00 秒
    [検査結果] OK
    ```
    
2. ClaudなどのAIにm2tsのmediainfo結果を送ってBD規格との相違が無いか確認してもらう（手っ取り早いので）
3. **ISOの中身**: 出力されたISOをマウントして、直下に `BDMV` と `CERTIFICATE` があるか
3. **UDFのバージョン**: ImgBurnでISOを開いて、2.50になっているか
4. **PCでの再生確認**: ISOの中のm2tsファイル("\BDMV\STREAM\00000.m2ts")をVLCなどで、先頭、中盤、終盤をシークして、コマ飛びがないか。終盤で口の動きと音が合っているか
5. AUDの設定確認：以下のコマンドを実行(動画パスはISOをマウントしたときのm2ts動画のパスに変えて)
    
    ```bash
   ffmpeg -v trace -i "F:\BDMV\STREAM\00000.m2ts" -t 1 -an -c:v copy -bsf:v trace_headers -f null - 2>&1 | Select-String "Access Unit Delimiter" | Select-Object -First 3
    ```
    以下のような出力があればOK
    ```bash
    [trace_headers @ 0000027e5c536040] Access Unit Delimiter
    ```
